## How it is served

```
nicsfivenips.com   ─┐
www.nicsfivenips.com├─ Cloudflare (proxied CNAMEs) ─ breathwork tunnel ─ 127.0.0.1:8104
nicks.paulayre.co.uk┘                                                      serve.py
```

- Tunnel: `bda0749a-02bb-42e5-b5ad-f1a170023d1d`, ingress in `~/.cloudflared/config.yml`
- Server: `serve.py`, kept alive by launchd `com.paulayre.nicks`
- Password: `iain` / `iains5nips` (hardcoded; Paul has confirmed this is fine)
- Restart the tunnel by kill-and-relaunch, **never SIGHUP**, SIGHUP kills it

## Opening the door

```bash
./open-day.sh on 2026-10-31   # no password for that whole day
./open-day.sh for 10          # ten minutes, for a quick demo
./open-day.sh off             # lock it now
./open-day.sh status          # state, plus what a stranger actually sees
```

`OPEN-UNTIL` holds an expiry timestamp. `serve.py` re-reads it **on every
request**, so changes are instant, no restart is needed, and it **re-locks
itself**. Anything missing, expired or malformed counts as locked: it fails
shut, never open.

`status` resolves through 1.1.1.1 deliberately. This Mac's own resolver held
GoDaddy's stale records for hours after the domain move and cheerfully reported
the site as OPEN while it was locked. Never trust the local cache here.

## The watchdog

`watchdog.sh`, run every 15 minutes by launchd `com.paulayre.nicks-watchdog`.

It **arms itself**: it does nothing unless `OPEN-UNTIL` is live, so unlocking
the site for a day automatically guards that day, and it costs nothing the rest
of the year. It alerts Paul on a state change, re-alerts at most hourly while
still broken, and sends an all-clear on recovery. All six paths were tested with
a stubbed sender.

Note it uses `StartCalendarInterval`, not `StartInterval`, which is wedged on
this Mac.

### Known limit

The watchdog runs *on* the Mac, so it cannot tell you the Mac is asleep or off.
That is the biggest risk on the day. It does catch a dead tunnel, a dead
`serve.py`, and a site that is locked when it should be open. An external
monitor on the URL would close the gap; none is set up.

## DNS gotcha

GoDaddy's old nameservers still answer for `nicsfivenips.com` with a "Launching
Soon" parking page, and the `.com` delegation TTL is 48 hours. A stale resolver
therefore shows the parking page rather than failing outright, which is exactly
what Paul's phone did on 20 Sep. It is not a fault to debug: airplane mode, or
swapping wifi for mobile data, clears it.
